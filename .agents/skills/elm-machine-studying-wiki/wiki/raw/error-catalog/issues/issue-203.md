# Issue #203: "type applications should start with a type atom" caused by 

**State:** `OPEN` | **Author:** @RJWoodhead | **Source:** [https://github.com/elm/error-message-catalog/issues/203](https://github.com/elm/error-message-catalog/issues/203)

## Description

Under certain circumstances, incomplete type annotations cause an unhelpful error message.

Replication case:

```
foo : List -> List
foo list =
    (List.take 0 list) ++ (List.take 0 list)

```
Note the type annotation should be `List a -> List a` but due to insufficient lattenization, this was not done.

The full error generated by this is:

```
-- TYPE MISMATCH ---------------------------------------------------------------

The left argument of (++) is causing a type mismatch.

4|      List.take 0 list) ++ (List.take 0 list)
        ^^^^^^^^^^^^^^^^
(++) is expecting the left argument to be a:

    appendable

But the left argument is:

    elm-make: type applications should start with a type atom

```
Simpler functions do not generate this error message, the ++ is apparently needed.

Making things more confusing to this newbie, the error message as displayed in atom (as opposed to elm-make in the console) is just the last line with the error position of line 1, col 1 [this is not directly a compiler problem, of course, I just mention it for completeness]

Interestingly, running the code on http://elm-lang.org:1234/try generates a reasonable error message, but http://elm-lang.org/try generates the message above.

My thanks to @halohalospecial on elm-slack for helping track this down and developing a minimal test-case
